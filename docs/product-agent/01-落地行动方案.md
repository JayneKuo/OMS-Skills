# Product Agent 落地行动方案

## 1. 目标定位

Product Agent 第一版定位为 **OMS 内部数据驱动的多渠道商品运营助手**。

它优先基于 OMS 商品中心、渠道商品、库存、订单和销售表现数据，完成：

1. 商品事实查询
2. 渠道商品状态诊断
3. 商品内容与图片优化建议
4. 多渠道刊登规划
5. 轻量销售表现联动分析

涉及市场机会、竞品表现、关键词搜索量、平台趋势、评论洞察、广告表现和转化率时，只有在接入外部市场/平台数据后才能输出高置信度结论；否则只能输出初步建议并标注数据不足。

---

## 2. 能力分级

| 级别 | 能力类型 | 数据来源 | 当前策略 |
|---|---|---|---|
| Level 1 | OMS 事实能力 | 商品中心、渠道商品、库存、价格、同步/审核状态 | 强承诺，优先落地 |
| Level 2 | OMS 分析能力 | `oms_analysis.sku_sales`、`channel_performance`、`order_trend` | 复用并增强过滤能力 |
| Level 3 | 经营建议能力 | 商品资料、渠道规则、用户输入、销售表现 | 可输出建议，需标注置信度 |
| Level 4 | 外部市场/竞品能力 | Jungle Scout/Helium10/SP-API/Shopify/TikTok/广告/评论数据 | 当前不支持，后续新增 |

---

## 3. 当前 Skill 支持情况

| 目标能力 | 当前支持 | 依赖 | 处理方案 |
|---|---|---|---|
| 商品基础查询 | 已定义，未实现 API | `product_query` | 确认商品 API 后实现 |
| 渠道商品状态 | 已定义，未实现 API | `product_query` | 确认渠道商品 API 后实现 |
| 同步/审核/上架诊断 | 已定义，依赖查询证据 | `product_diagnosis` + `product_query` | 等 `product_query` 提供结构化证据 |
| 最近 SKU 销量 | 现有基础支持 | `oms_analysis.sku_sales` | 增强 filters/time_range |
| 渠道表现 | 现有基础支持 | `oms_analysis.channel_performance` | 增强商品维度过滤 |
| 商品内容优化 | 可 prompt 型落地 | `product_optimization` | 第一版可先上线，标注数据边界 |
| 图片优化建议 | 可建议，不一定能看图 | `product_optimization` | 无图像工具时只基于描述和规范 |
| 多渠道刊登规划 | 已定义，依赖上游结果 | `product_listing_planner` | 上游稳定后落地 |
| 竞品分析 | 不支持 | 新增外部数据 skill | 后续新增 `market_product_research` |
| 关键词搜索量 | 不支持 | 外部 API | 后续接 Helium10/JungleScout/SP-API 等 |
| TikTok/平台趋势 | 不支持 | 外部 API | 后续接平台 analytics 或趋势数据 |

## 4. 推荐 Skill 组合

### MVP 挂载

```md
Product Agent
├── product_query
├── product_diagnosis
├── product_optimization
└── product_listing_planner
```

### 需要联动的现有 Skill

```md
oms_analysis
├── sku_sales
├── channel_performance
└── order_trend
```

Product Agent 遇到销售表现问题时，应按以下方式联动：

```md
用户问：这个商品最近卖得怎么样？

1. product_query
   - 确认 SKU / SPU / productId / channel
2. oms_analysis(intent=sku_sales)
   - 查询近 7 / 30 天销量、销售额、订单数
3. 如涉及渠道比较：oms_analysis(intent=channel_performance)
4. Product Agent 汇总成业务回答和前端 visual_blocks
```

## 6. Phase 2：增强 oms_analysis 以支持商品表现分析

### 状态

已完成第一轮实现：

- `oms_analysis` MCP tool 已支持 `filters` / `time_range` JSON 字符串入参。
- `SkuSalesAnalyzer` 已支持按 SKU / channel / shop 过滤。
- `ChannelPerformanceAnalyzer` 已支持按 SKU / channel / shop 过滤。
- `AnalysisResult` 已补齐 `details` 字段，以承载商品表现明细。
- 已新增并通过最小 pytest 验证。

### 目标

让 Product Agent 能稳定回答：

- 这个 SKU 最近 7 / 30 天销量怎么样？
- 这个商品 GMV 是多少？
- 这个商品在哪个渠道表现最好？
- 这个商品是否滞销？
- 这个商品适合继续铺渠道吗？

### 当前问题

`AnalysisRequest` 已有：

```py
identifier
merchant_no
intent
query
time_range
filters
```

但 MCP tool `oms_analysis(...)` 当前只暴露：

```py
identifier
merchant_no
intent
query
```

没有暴露：

```py
time_range
filters
```

### 修改计划

#### 6.1 扩展 MCP 入参

修改 `.kiro/skills/oms-agent/mcp_server.py` 中的 `oms_analysis`：

```py
def oms_analysis(
    identifier: str | None = None,
    merchant_no: str | None = None,
    intent: str | None = None,
    query: str | None = None,
    filters: str | None = None,
    time_range: str | None = None,
) -> str:
```

`filters` JSON 示例：

```json
{
  "sku": "SKU001",
  "spu": "SPU001",
  "product_id": "P001",
  "channel_code": "amazon",
  "shop_id": "SHOP001",
  "top_n": 10
}
```

`time_range` JSON 示例：

```json
{
  "start": "2026-04-11T00:00:00Z",
  "end": "2026-05-11T23:59:59Z"
}
```

#### 6.2 增强 SkuSalesAnalyzer

文件：`.kiro/skills/oms-analysis/scripts/oms_analysis_engine/analyzers/sku_sales.py`

需要支持：

- 指定 SKU
- 指定 SPU 映射到多个 SKU（依赖 product_query）
- 指定 channel_code
- 指定 shop_id
- 指定 time_range
- 返回销量、销售额、订单数、热销/正常/滞销标签

#### 6.3 增强 ChannelPerformanceAnalyzer

文件：`.kiro/skills/oms-analysis/scripts/oms_analysis_engine/analyzers/channel_performance.py`

需要支持：

- 指定 SKU / SPU / product_id
- 指定 channel_code
- 指定 shop_id
- 返回该商品在不同渠道的订单数、GMV、客单价、异常率、取消率、完成率

#### 6.4 验证场景

- 查询指定 SKU 近 30 天销量
- 查询指定 SKU 在 Amazon 渠道近 30 天 GMV
- 查询某商品在多个渠道的表现对比
- 查询某 SKU 是否滞销

## 7. Phase 3：确认商品中心与渠道商品 API

### MVP 状态

已落地最小可用 `product_query` runtime：

- `product_query(...)` MCP tool 可接收 `identifier` / `merchant_no` / `intent` / `filters`。
- `identity_for_performance` 可输出 `performance_query`，直接衔接 Phase 2 `oms_analysis`。
- `inventory_price` 可基于现有库存 API 返回 SKU 库存和价格摘要。
- 商品中心主档、渠道商品、同步/审核/上架状态仍需后续确认真实 API 后接入。
- 已接入前端确认的商品中心 SPU 接口：`/baseservice/rpc-api/product/spu/page` 与 `/baseservice/rpc-api/product/spu/get/{id}`。
- 已接入前端确认的渠道商品接口：`/baseservice/rpc-api/channel-product/page` 与 `/baseservice/rpc-api/channel-product/get/{productId}`。
- 已接入前端确认的发布历史接口：`/baseservice/rpc-api/publish-history/page`，用于后续诊断发布/审核失败。

## 8. Phase 4：商品表现组合入口

### MVP 状态

已新增 `product_performance(...)` 组合入口：

- 先调用 `product_query(identity_for_performance)` 生成 `performance_query`。
- 再调用 `oms_analysis(intent=sku_sales)` 查询 SKU 销量、GMV 和订单表现。
- `include_channel=true` 时额外调用 `oms_analysis(intent=channel_performance)` 查询渠道表现。
- 返回 `product_query`、`sku_sales`、可选 `channel_performance` 的统一 JSON，避免调用方手动编排多工具。

### 目标

输出 `product_query API mapping`，确认以下数据来源：

1. 商品主档列表/详情 API
2. SKU / SPU 查询 API
3. 渠道商品列表/详情 API
4. 商品与渠道商品映射 API
5. 同步任务 / 同步日志 API
6. 审核状态 API
7. 图片与属性完整度来源
8. 价格来源
9. 库存来源

### 当前线索

现有文档中已有：

- 商品页面：`/product-list`
- 商品详情页面：`/product-list/{productId}`
- SKU 主数据：`ProductDTO`
- 商品物理属性：length / width / height / weight
- 类目、标签、组合商品数据
- 文档提示：SKU 主数据仍需独立查询 API

## 14. 验收标准

### Product Agent

- 能使用前端传入的商品/渠道上下文，不重复追问。
- 能区分查询结果、分析结论、推荐建议和估算结果。
- 不编造市场/竞品/销售数据。

### product_query

- 能返回商品中心和渠道商品真实状态。
- 能标注数据完整度。
- 能提供前端可渲染的状态卡片和表格。

### oms_analysis 联动

- 能按 SKU / channel / time_range 查询销量和 GMV。
- 能返回商品维度的渠道表现。

### product_diagnosis

- 每个诊断结论都有 evidence。
- 每条建议有 precondition、risk、priority、expected_effect。

### product_optimization

- 渠道内容有差异化。
- 没有市场/竞品数据时不会输出确定性市场结论。

### product_listing_planner

- 能输出可执行刊登步骤。
- 能区分阻塞项、建议项和可选项。
